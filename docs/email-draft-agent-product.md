# メール下書き Agent プロダクト構想

## 最終的に作るもの

このチュートリアルの最終課題では、OpenAI Agents SDK を使って「メール下書き Agent」を作る。

ユーザーがメールの目的、相手、伝えたい内容、文体を入力すると、Agent が自然なメールの件名と本文を下書きする。

## プロダクトの目的

メール作成で発生しやすい次の負担を減らす。

- 何を書けばよいか整理する負担
- 件名を考える負担
- 丁寧な表現に直す負担
- 長すぎる文章を簡潔にする負担
- 相手や場面に合うトーンへ調整する負担

## 想定ユーザー

- ビジネスメールをよく書く人
- 日本語の丁寧なメール表現に不安がある人
- 要点はあるが、自然な文章にまとめるのが苦手な人
- メールの返信や依頼文を素早く作りたい人

## 最終形のイメージ

```text
ユーザーが目的・相手・伝えたい内容・トーンを入力する
↓
Agent が不足情報を判断する
↓
必要なら確認質問をする
↓
件名と本文の下書きを作る
↓
ユーザーが修正依頼を出す
↓
Agent がトーンや長さを調整する
↓
安全上問題がある内容は guardrail で止める
↓
trace や eval で品質を確認する
```

## Agent の基本役割

Agent 名の候補:

```text
Email Draft Assistant
```

役割:

```text
ユーザーの依頼内容を整理し、相手と目的に合った自然なメール下書きを作成する。
```

## 入力例

```text
取引先に、明日の会議を30分後ろ倒しできるか相談するメールを書いて。
丁寧だけど堅すぎない感じで。
```

```text
採用面接の日程調整メールに返信したい。
来週火曜と木曜の午後なら空いていると伝えたい。
```

```text
上司に体調不良で午前休を取りたいと連絡するメールを書いて。
短めで。
```

## 出力例

```text
件名: 明日の会議時間についてのご相談

本文:
〇〇様

お世話になっております。
明日予定している会議について、開始時間を30分ほど後ろ倒しすることは可能でしょうか。

急なご相談となり恐縮ですが、ご都合を確認いただけますと幸いです。

よろしくお願いいたします。
```

## 最初に作る最小機能

第2回では、まず次だけを作る。

- 1つの Agent
- 1つの入力文
- 1つのメール下書き出力

まだ次の機能は入れない。

- tool
- 会話状態
- 複数 Agent
- guardrail
- eval

## 段階的に追加する機能

### Step 1: 最小 Agent

ユーザーの依頼を受け取り、メールの下書きを返す。

### Step 2: Agent 定義の整理

`src/index.ts` に直書きしていた Agent を `src/agents/emailDraftAgent.ts` に分ける。

### Step 3: 構造化出力

件名と本文を分けて返す。

例:

```json
{
  "subject": "...",
  "body": "..."
}
```

### Step 4: Function tool

メール文面の改善に使う小さな tool を作る。

候補:

- トーン変換 tool
- 文字数チェック tool
- 必須項目チェック tool

### Step 5: 会話状態

ユーザーが追加修正できるようにする。

例:

```text
もう少し柔らかくして
```

```text
本文を半分くらいに短くして
```

### Step 6: 複数 Agent

役割を分ける。

候補:

- 要件整理 Agent
- 下書き作成 Agent
- トーン調整 Agent
- 最終チェック Agent

### Step 7: Guardrails

不適切な内容や危険な依頼を止める。

例:

- なりすましメール
- 詐欺的な文面
- 脅迫的な内容
- 個人情報を過剰に含む依頼

### Step 8: Tracing

Agent がどのように判断したかを trace で確認する。

確認したいこと:

- instructions が効いているか
- tool が必要なときだけ呼ばれているか
- guardrail が正しく動いているか
- 余計な回り道をしていないか

### Step 9: Evals

メール下書きの品質を評価する。

評価観点:

- 目的に合っているか
- 件名が自然か
- 本文が分かりやすいか
- トーンが指定通りか
- 過度に長くないか
- 不要な情報を追加していないか

## 完成条件

最終課題として、次を満たすことを目標にする。

- メール下書き用の Agent がある
- 件名と本文を出力できる
- ユーザーの追加修正に対応できる
- 少なくとも1つの function tool がある
- 少なくとも1つの guardrail がある
- trace を確認できる
- 簡単な eval 観点を持っている

## 実装で守ること

- API キーはコードに直接書かない
- `OPENAI_API_KEY` を環境変数として使う
- 最初は小さく作る
- 動く状態を保ちながら機能を足す
- 公式ドキュメントの Agents SDK の流れに沿う
